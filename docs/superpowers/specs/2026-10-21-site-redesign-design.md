# 공과대학 학생회 [여정] 홈페이지 리디자인 설계

- 작성일: 2026-10-21
- 브랜치: `redesign/2026-campus` (Trip_Portal_FE)
- 상태: 설계 승인 완료, 스펙 리뷰 대기

## 1. 목표와 성공 기준

**목표**: 사용자·관리자 페이지 전체를 리디자인한다. 기존 기능은 모두 유지하고, "다른 사이트가 됐다"는 느낌이 들지 않을 정도로 변화 폭을 제한한다. 대학생 사용자를 고려해 재밌고 귀여운 아이콘을 적극적으로 쓴다.

**성공 기준**
1. 기존 라우트, API 호출, 권한 분기, `alert`/`confirm` 문구가 모두 그대로 동작한다.
2. 로고, 네이비 메인 컬러, Pretendard GOV, 메뉴 구성(정보 구조)이 유지되어 기존 사용자가 같은 사이트로 인식한다.
3. 사용자 페이지는 모바일(360px)에서 가로 스크롤 없이 모든 기능을 쓸 수 있고, 데스크톱(1280px)에서도 자연스럽게 확장된다.
4. 관리자 페이지는 데스크톱 기준이며, 모바일에서도 조회와 처리가 가능하다.
5. 백엔드 저장소의 코드 변경은 0건을 목표로 한다(아래 6절 예외 규칙 참고).
6. `npm run build`와 `npm run lint`를 통과한다.

## 3. 기반

### 3.1 디자인 토큰: `src/styles/tokens.css`
- **브랜드**: `--color-navy-900: #001f3f`, `--color-navy-700: #004085`, `--color-saegil: #3986c6`, `--color-sky: #A9D0F5`
- **중립**: 회색 50~900 단계, 배경 `#f8f9fa`, 카드 `#ffffff`, 경계선 `#e3e8ee`
- **상태색** (배경/글자 쌍)
  - 신청 = 주황(`#fff3d6`/`#b45309`)
  - 대여중 = 파랑(`#dbeafe`/`#1d4ed8`)
  - 연체 = 빨강(`#fee2e2`/`#b91c1c`)
  - 반납완료 = 초록(`#dcfce7`/`#15803d`)
  - 백엔드 상태 값은 `신청`/`미반납`/`반납완료` 세 가지이고, `미반납`은 '현재 대여 중'이라는 뜻이다. 화면에는 값을 그대로 표시하고 색만 정한다: `미반납`은 반납기한(대여일 + 4일) 당일까지 파랑, 그다음 날부터 빨강이다.
  - NEW 배지 = 빨강, 고정 = 파랑
- **간격**: 4px 단위(`--space-1`=4px … `--space-8`=32px …)
- **둥글기**: 카드 12px, 버튼·입력칸 10px, 배지 999px
- **그림자**: 2단계(`--shadow-sm`, `--shadow-md`)
- **타이포**: Pretendard GOV 유지. 모바일 기준은 본문 15px, 소제목 18px, 페이지 제목 22px이고, `≥1024px`에서 한 단계씩 키운다.
- **호환성**: 기존 변수(`--main-navy`, `--second-navy`, `--saegil-blue`, `--background-color`, `--border-radius`, `--box-shadow` 등)는 삭제하지 않고 새 토큰을 참조하도록 바꾼다. 리디자인에서 제외한 티저 페이지가 깨지지 않게 하기 위해서다. `index.css`에 있는 shadcn용 oklch 변수는 건드리지 않는다.

### 3.2 공통 컴포넌트: `src/components/ui/`
각 파일은 JSX와 같은 이름의 CSS 한 쌍으로 구성하고, 기존 코드처럼 일반 CSS와 `className`을 쓴다.

| 컴포넌트 | 역할 |
|---|---|
| `Button` | variant: primary / ghost / danger, size: md / lg. `as`로 Link·a 렌더링 지원 |
| `Card` | 흰 배경, 둥글기, 그림자 컨테이너 |
| `Badge` | tone: pending / ongoing / overdue / done / new / pinned / neutral |
| `PageHeader` | 제목, 설명, 오른쪽 액션 슬롯 |
| `Field` | 라벨 위 고정 입력 래퍼(input / select / textarea) |
| `EmptyState` | 빈 결과·오류 안내(아이콘과 문구) |
| `Spinner` | 로딩 표시. 기존 "로딩 중..." 텍스트 대체 |
| `BottomBar` | 모바일 하단 고정 액션 바. safe-area 여백 반영 |
| `ResponsiveTable` | `columns`·`rows`를 받아 `≥768px`(관리자는 `≥1024px`)에서는 표, 그 아래에서는 카드 목록으로 렌더링 |
| `Toggle` | 스위치(눈송이 효과, 공지 고정) |
| `Icon` | Lucian 아이콘 React 래퍼(3.3) |

### 3.3 아이콘
- **Lucian Icons** (v2.0.13, MIT, 움직임·컬러)
  - `lucian-icons` 스킬의 CLI로 필요한 모듈만 `src/vendor/lucian-icons/`에 반입한다.
  - 라이선스 고지를 유지한다.
  - `Icon` 래퍼가 맡는 일: 마운트·언마운트 생명주기, `prefers-reduced-motion` 대응, 장식용일 때 `aria-hidden` 처리, 단독 의미가 있을 때 한국어 `label` 지정.
  - 상태가 있는 아이콘(벨, 다운로드 등)은 실제 상태가 바뀔 때만 `setState`를 호출한다. 클릭했다고 성공으로 표시하지 않는다.
- **사용처 – Lucian**: 홈 바로가기(대여 신청, 대여 확인, 성심지도), 대여 완료 체크, 공지 첨부 다운로드, 관리자 사이드바 주요 메뉴, 승인 대기 벨, 점검 화면 렌치, 관리자 로그인 자물쇠, 로그 엑셀 다운로드
- **사용처 – lucide-react** (이미 설치됨, 정적 선 아이콘): 검색, 화살표, 닫기, 메뉴, 메타 정보(조회수, 작성일, 첨부), 표 액션(수정, 삭제), 헤더 메뉴 아이콘 등 나머지 일반 UI 전부
- 현재 쓰는 이모지 아이콘(📦 🔍 🛠️ ✔️ 📄 💾 ❄️ 👋 등)은 모두 위 두 가지 아이콘으로 교체한다.
- 구체적인 아이콘 ID와 버전은 구현 계획 단계에서 `lucian-icons search`로 확정하고 표로 기록한다.

### 3.4 반응형과 접근성
- **중단점**: `≥768px` 태블릿, `≥1024px` 데스크톱. 사용자 페이지 CSS는 모바일 기본 스타일에 `min-width` 미디어쿼리를 더하는 방식으로 작성한다.
- **터치 영역**: 최소 44×44px
- **포커스 표시**: `:focus-visible` 링은 새길 블루 2px
- **그 외**: 360px에서 가로 스크롤 없음, `prefers-reduced-motion`이면 애니메이션 정지

### 3.5 변경하지 않는 것
- **라우트와 코드**: 라우트 경로와 페이지 연결(`App.jsx`, 관리자 레이아웃 래핑만 5.1절에 따라 변경), API 엔드포인트와 요청·응답 처리 코드, 페이지 상태 로직
- **이스터에그와 효과**: 코나미 커맨드, 푸터 5회 터치, 공룡 게임 로직, 눈송이 효과(`react-snowfall`), `ClickSpark`, `DomeGallery`의 동작과 파라미터
- **권한**: `ProtectedRoute`, `localStorage`의 `isAdmin`/`adminRole` 사용 방식
- **안내 방식**: 모든 `alert`/`confirm`의 문구와 시점

## 4. 사용자 페이지

### 4.1 공통 셸
- **Header**: 네이비 그라데이션, 로고, 메뉴 항목과 순서를 유지한다(공지사항, 대여사업 ▸ 대여 신청·신청/대여 확인, 성심지도, 조직도, 단과대 및 학과, 2025 새길 외부 링크).
  - 모바일: 햄버거를 누르면 오른쪽 슬라이드 패널이 열리고, '대여사업' 하위 메뉴는 펼침형이다. 메뉴마다 lucide 아이콘을 붙인다. 바깥을 누르거나 메뉴를 고르면 닫힌다(기존 동작).
  - 데스크톱: 드롭다운

- **FloatingSNS**: 위치와 기능은 유지하고 버튼 모양만 토큰에 맞춘다.
- **MainLayout**: 헤더 높이 여백(`70px`)을 토큰 변수로 옮긴다.

### 4.2 홈 `/`: 바로가기 우선
1. **히어로**
   - DomeGallery 배경, 어둡게 덮는 오버레이, 문구("제4대 공과대학 학생회 [여정]", "변화를 새길, 우리의 여정!")를 유지한다.
   - 그 위에 바로가기 버튼 3개(대여 신청 `/borrow`, 대여 확인 `/check`, 성심지도 `/campusmap`)를 Lucian 아이콘과 함께 둔다. 모바일에서는 크게 누를 수 있는 버튼으로 보여준다.
2. **학교 바로가기**: 기존 5개 링크(학교 홈페이지, 학사일정, 트리니티, 사이버캠퍼스, 공결허가원)를 칩 형태로 한 줄에 둔다. 모바일에서는 가로 스크롤한다.
3. **공지 카드**
   - 기존 5개 표시를 유지하고 "더보기 →"를 둔다.
   - 📌 고정 배지와 NEW 배지(작성 3일 이내, 프론트에서 계산)를 붙인다.
4. **D-Day 카드**: 기존 `dDayInfo` 로직을 그대로 쓰고 독립 카드로 분리한다.
5. **인스타 슬라이더**: 이전·다음 버튼, 페이지 표시, 링크 이동, 이미지 URL 처리(`getFullImgUrl`)를 유지한다. 화살표는 lucide로 바꾼다.
6. **배치**: 모바일은 1→2→3→4→5 순으로 쌓는다. 데스크톱은 3을 왼쪽 넓은 열에, 4·5를 오른쪽 열에 둔다.
7. **점검 중 화면** (`isServerDown`): 같은 카드 스타일에 렌치 Lucian 아이콘을 쓴다. 문구(05:00~06:00 정기 점검, 이용 가능 서비스)와 학교 바로가기 칩을 유지한다.

### 4.3 대여 신청 `/borrow`: 단계별 마법사
- **단계 상태**: 컴포넌트 안의 `step` 상태(1 = 물품 선택, 2 = 정보 입력)로 관리한다. URL은 `/borrow` 그대로다.
  - 2단계로 넘어갈 때 `history.pushState`로 기록을 하나 추가하고, `popstate`가 발생하면 1단계로 돌아간다. 장바구니와 입력값은 그대로 남는다.
  - 단계 표시: 물품 → 정보 → 완료
- **1단계**
  - 검색(물품명 포함 검색, 기존 `filteredItems` 로직), 카테고리 탭(기존 `categories`)을 둔다.
  - 물품은 한 줄 목록으로 보여준다(아이콘, 이름, 남은 수량, 선택 원형). 품절 물품은 흐리게 하고 누를 수 없다(기존 `toggleItem` 가드).
  - `BottomBar`: "N개 선택됨 · 다음 →". 선택이 0개면 비활성이다.
  - 데스크톱에서는 3~4열 격자로 보여주고, 하단 바 대신 카드 아래 버튼을 둔다.
- **2단계**
  - 선택한 물품 요약 태그와 '수정' 버튼(1단계로 이동)을 둔다.
  - `Field` 4개: 이름, 학번(`type="number"`, min/max 유지, `inputMode="numeric"`), 학과(`/api/departments` select), 전화번호(`type="tel"`)
  - `BottomBar`: "← 이전 | 대여 신청하기"
  - 제출 로직(`handleSubmit`, payload, 반납일 +4일 계산, `/success` state 전달, `alert` 문구)은 그대로 쓴다.
- **로딩과 오류**: 로딩은 `Spinner`로 표시한다. 물품 목록 로드 실패 `alert`는 유지하고, 검색 결과가 없으면 `EmptyState`를 보여준다.

### 4.4 신청 확인 `/check`
- 이름·학번 폼(기존 `POST /api/check`)을 둔다. 모바일에서는 세로로 쌓고, 데스크톱에서는 한 줄로 둔다.
- 결과
  - 상단에 "{이름}님의 기록 · 학번"을 표시한다.
  - 각 기록은 카드로 보여준다: 상태 `Badge`(3.1절 규칙: 신청 주황, 미반납은 기한 내 파랑·기한이 지나면 빨강, 반납완료 초록, 그 외 값은 중립색), 물품, 신청·대여일, 반납기한.
- 오류 메시지와 "조회 결과가 없습니다"는 `EmptyState`로 보여준다.

### 4.5 완료 `/success`
- `location.state`가 없으면 `/`로 이동하는 기존 가드를 유지한다.
- 완료 체크 아이콘은 Lucian으로 바꾼다. 제목은 기존 문구를 유지한다.
- **안내 카드**: 공대방(N502) 방문 수령 안내, 24시간 자동 취소 경고, 대여일, 반납기한, 물품 태그
- **버튼**: "메인으로 돌아가기"(기존)와 "신청 확인하기"(`/check`로 이동, 추가)

### 4.6 공지 목록 `/notices`
- 검색(제목/내용 select, Enter 키, 검색 버튼), 페이지당 10개 페이지네이션, 빈 상태 문구 2종 등 기존 로직을 유지한다.
- **모바일**: 카드 목록. 제목, 배지(📌 고정, NEW), 작성자, 날짜, 조회수, 📎 첨부 개수(`files.length`)를 보여준다. 고정글은 왼쪽 파란 띠로 구분한다.
- **데스크톱**: 정돈된 표(작성일, 제목, 작성자, 조회수)를 유지하고 제목 옆에 배지와 첨부 아이콘을 붙인다.

### 4.7 공지 상세 `/notices/:id`
- 기존 로직을 유지한다: 중복 요청 방지 `ref`, `increment: 'true'` 조회수 증가, URL 자동 링크(`renderContent`), 이미지 미리보기 격자(`isImageFile`), "목록으로" 버튼.
- **헤더**: 제목과 메타 정보(작성자, 작성일, 조회수)를 lucide 아이콘과 함께 보여준다. 모바일 본문은 15~16px, 줄간격 1.7이고, 데스크톱 본문 최대 폭은 720px이다.
- **첨부파일**: 접기를 유지한다(`isFilesOpen`). 토글 버튼은 "첨부파일 N개"와 chevron으로 구성한다. 펼치면 확장자 배지, 파일명, Lucian 다운로드 아이콘이 달린 파일 카드가 나온다. 다운로드 URL은 기존 그대로다. 첨부가 없으면 "첨부파일 없음"을 표시한다.

### 4.8 스타일만 다듬는 페이지 (배치 유지)
- 대상: 성심지도(`MapPage`, `CampusMap`, `FacilityModal`), 조직도(`OrganPage`), 단과대 및 학과(`DepartmentPage`), 약관 4종(Terms, Privacy, EmailRefusal, Credits)
- 적용 범위: 토큰, `Card`, `Button`, 아이콘을 적용하고 모바일 간격과 타이포를 정리한다.
- 건드리지 않는 것: 지도 클릭 영역, `CampusMapData.js` 데이터, 학과 데이터 구조

### 4.9 공룡 게임
- 게임 로직과 캔버스는 그대로 둔다.
- 오버레이 배경, 닫기 버튼(lucide X), 점수와 안내 텍스트만 토큰에 맞춘다.

## 5. 관리자 페이지

### 5.1 AdminLayout: `src/layouts/AdminLayout.jsx`
- **적용 방식**: 기존 `AdminHeader`를 대체한다. `App.jsx`의 `ProtectedRoute` 아래 라우트를 `AdminLayout`으로 감싸고, 각 관리자 페이지에서 `<AdminHeader />` 호출을 제거한다.
  - 현재 관리자 라우트는 `MainLayout` 안에 있어서 사용자 헤더(`Header`)가 함께 렌더링된다.
  - `App.jsx`에서 `/admin`(로그인)과 `ProtectedRoute` 묶음을 `MainLayout` 밖으로 옮긴다. 로그인 화면은 레이아웃 없이 단독으로 띄우고, 보호된 라우트는 `<Route element={<ProtectedRoute />}><Route element={<AdminLayout />}>…</Route></Route>`로 감싼다.
  - **경로 문자열과 페이지 컴포넌트 연결은 하나도 바뀌지 않는다.** 바뀌는 것은 레이아웃 래핑뿐이다(3.5절의 "라우트 구조 유지"는 경로와 페이지 연결을 뜻한다).
  - Footer와 이스터에그 래퍼는 지금처럼 모든 경로에 렌더링된다.
- **데스크톱 (`≥1024px`)**
  - 왼쪽 네이비 사이드바. 펼치면 240px(아이콘과 이름), 접으면 72px(아이콘만, 마우스를 올리거나 포커스하면 툴팁)
  - 접힘 상태는 `localStorage['adminSidebarCollapsed']`에 저장한다(읽고 쓸 때 try/catch로 감싼다).
- **메뉴**
  - 대시보드
  - 콘텐츠: 공지사항, 인스타 관리(`adminRole === 'master'`), 티저 이벤트(master)
  - 대여 사업: 대여 승인(대기 건수 배지), 반납 관리, 재고 관리, 전체 기록
  - 하단: 사용자 홈 ↗, 로그아웃
  - 로그아웃 동작은 기존 `handleLogout`과 같다: confirm → `POST /api/admin/logout` → `localStorage` 정리 → alert → `/`로 이동.
  - 현재 경로에 해당하는 메뉴를 강조한다.
- **`<1024px`**: 상단바(햄버거, 현재 페이지 제목, 로고)가 생기고 사이드바는 왼쪽 서랍 메뉴가 된다. 서랍은 배경을 누르거나, 메뉴를 고르거나, Esc를 누르면 닫힌다.
- **승인 대기 배지**: `GET /api/admin/requests` 결과의 `data.length`로 표시한다.
  - 레이아웃이 처음 마운트될 때와 승인·거절 처리 직후에 다시 읽는다. 승인 페이지는 레이아웃이 제공하는 `refreshPendingCount`(context)를 호출한다.
  - 주기적인 폴링은 하지 않는다.
- **티저 이벤트 화면**: 레이아웃만 적용하고 내용은 손대지 않는다.

### 5.2 대시보드 `/admin/dashboard`
- **요약 카드 3개**
  - 금일 대여: `/api/admin/dashboard`의 `today_count`
  - 승인 대기: `/api/admin/requests` 개수
  - 대여 중: `/api/admin/ongoing` 개수
  - 카드를 누르면 각각 전체 기록, 승인, 반납 페이지로 이동한다.
- **눈송이 효과**: master에게만 `Toggle`로 보인다. 기존 GET/POST와 alert 문구를 유지한다.
- **최근 대여 기록**: 최신 5건을 `ResponsiveTable`로 보여준다(대여시각, 이름, 학번, 물품, 상태 `Badge`).
- 기존 로그인 체크(`isAdmin` 없으면 alert 후 `/admin`으로 이동)를 유지한다.

### 5.3 대여 관리
- **승인 `/admin/borrow/approve`**
  - 목록은 `ResponsiveTable`로 보여준다.
  - 담당자 입력 흐름(`selectedId`, `handlerName` → `POST /api/admin/approve`)은 그대로 두고 모달 디자인만 정리한다.
  - 거절은 기존 confirm → `POST /api/admin/reject` 흐름을 유지한다.
  - 처리가 성공하면 대기 건수 배지를 새로 읽는다.
- **반납 `/admin/borrow/return`**: 같은 패턴이다(`/ongoing`, `POST /api/admin/return`).
- **재고 `/admin/borrow/stock`**
  - 수량 편집, 전체 저장(`/stock/update`), 추가(`/stock/add`), 삭제(confirm → `/stock/delete`)를 유지한다.
  - 처음 불러온 값과 비교해서, 수정했지만 아직 저장하지 않은 줄을 강조한다(프론트에서 비교만 한다).
- **전체 기록 `/admin/borrow/log`**
  - `ResponsiveTable`로 보여준다.
  - 엑셀 다운로드 버튼은 Lucian download 아이콘으로 바꾼다. URL(`https://trip-api.cukeng.kr/api/admin/download_log`)과 동작은 그대로다.

### 5.4 콘텐츠 관리
- **공지 목록 `/admin/notices`**: `include_private` 조회와 삭제 confirm을 유지한다. 고정·공개 상태 `Badge`, 수정·삭제 아이콘 버튼, "새 공지" 버튼을 둔다.
- **공지 작성·수정**
  - 기존 필드를 모두 유지한다: 공개 여부(`is_public` 라디오를 세그먼트 버튼 모양으로 바꾸되 radio input과 `handleChange` 유지), 고정(`Toggle`, 기존 checkbox의 `name`/`checked`와 연결 방식 유지), 제목, 작성자, 내용.
  - 파일 다중 업로드: 기존 hidden input 클릭에 더해 끌어다 놓기(drag & drop)도 받는다. 같은 `handleFileChange` 경로로 처리한다.
  - 기존 첨부 삭제(confirm → `DELETE /api/notices/file/:id`), 수정 모드 로딩, alert 문구를 유지한다.
- **인스타 `/admin/instagram`**: 이미지와 링크 등록 폼, 게시물 카드 격자, 삭제를 둔다. 기존 검증 alert를 유지한다.

### 5.5 로그인 `/admin`
- 사용자 사이트 톤의 중앙 카드에 자물쇠 Lucian 아이콘과 비밀번호 `Field`를 둔다.
- 세션 확인(`check-session`), 로그인 POST, 역할 저장, 환영·오류 alert를 유지한다.

## 6. 백엔드 방침
- **현재 설계에 필요한 백엔드 변경은 없다.**
  - 공지 목록 API가 `files`와 `fixed`를 내려주고, 고정글 우선 정렬도 서버에서 한다.
  - 승인 대기와 대여 중 개수는 기존 목록 API의 길이로 구한다.
  - NEW 배지와 재고 미저장 비교는 프론트에서 간단히 계산하는 수준이다.
- **예외 규칙**: 구현 중에 프론트 로직이 과도해지는 경우가 생기면 그 지점에서 멈추고, 백엔드 변경안을 사용자에게 먼저 제시해 승인을 받은 뒤 진행한다. 예를 들면 같은 데이터를 여러 번 가공하거나, 페이지마다 같은 집계를 반복해야 하는 경우다.
- **호출 제한**: 공지 API의 rate limit(분당 30회)을 고려해, 관리자 배지는 폴링하지 않는다.

## 7. 검증 전략

### 7.1 로컬 백엔드 (운영 데이터 보호)
- 현재 `vite.config.js`의 개발 프록시는 운영 API(`https://trip-api.cukeng.kr`)를 바라본다. **데이터를 바꾸는 요청은 운영 서버에 보내지 않는다.**
- **프록시 대상 변경**: `vite.config.js`의 프록시 `target`을 `process.env.VITE_API_TARGET || 'https://trip-api.cukeng.kr'`로 바꾼다. 기본 동작은 지금과 같다.
- **로컬 실행 도구**: `tools/local-backend/` (FE 저장소)
  - `README.md`: Python 3.11 가상환경 생성, `Trip_Portal_BE/requirements.txt` 설치, `.env` 예시(`ADMIN_PASSWORD`, `SUB_PASSWORD`, `FLASK_SECRET_KEY`), 실행 방법을 적는다.
  - `seed_dev_data.py`: `Trip_Portal_BE/data/`에 더미 데이터(`stuff_ongoing.xlsx`, `borrow_log.xlsx`, `major.xlsx`, 건물·시설 xlsx, `database.db`의 공지·첨부·인스타 레코드)를 만든다. 대여 기록에는 상태별 데이터(신청, 대여중, 미반납, 반납완료)를 모두 넣는다. 이 폴더는 BE의 `.gitignore` 대상이라 **BE 저장소 파일은 바뀌지 않는다.**
  - 실행: BE는 `python app.py`(포트 5000), FE는 `VITE_API_TARGET=http://localhost:5000 npm run dev`
- **주의**: 로그 엑셀 다운로드 버튼은 운영 URL이 코드에 직접 들어 있다. 로컬에서는 버튼이 렌더링되는지만 확인하고 클릭하지 않는다.

### 7.2 페이지별 확인 항목
- 기존 기능 체크리스트를 화면에서 직접 확인한다: 3.5절과 4~5절에 "유지"로 적은 항목, alert·confirm 문구, 역할 분기(master와 sub).
- 폭 360 / 768 / 1280px에서 레이아웃이 깨지지 않고 가로 스크롤이 없어야 한다.
- 키보드 탐색(Tab 순서, Esc로 서랍·모달 닫기, 포커스 링)을 확인한다.
- `prefers-reduced-motion`이 켜지면 Lucian 애니메이션이 멈춰야 한다.
- Lucian 아이콘이 있는 화면을 여러 번 오가도 콘솔 오류나 중복 인스턴스가 생기지 않아야 한다.
- 티저 페이지가 지금과 똑같이 보이는지 회귀 확인한다.
- 각 단계를 마칠 때마다 `npm run build`와 `npm run lint`를 실행한다.
